# Known, deliberate divergences between parser/test/spec and
# jsonic/ts/test/spec. One filename per line (either side's name).
#
# Since the corpora split (this repo owns the engine's own surface,
# jsonic owns the relaxed-grammar corpus) a file existing on one side
# only is normal and no longer a failure. Entries here just keep the
# expected ones from being reported as INFO.
#
# alignment-utf8.tsv used to be listed here with a TODO to decide whether
# jsonic should carry it. It now lives in jsonic and runs in both of that
# repo's runtimes, so the entry is gone.
#
# These two exercise multi-byte source positions against the strict-JSON
# grammar, which is this repo's own surface.
include-json-utf8-errors.tsv
include-json-utf8.tsv

# Engine-only: pins the string.allowControl lexer option (raw control
# chars inside a string body) across both runtimes. It is a lexer-config
# fixture, not a grammar corpus — its first column is an option value,
# so the jsonic grammar suites cannot consume it.
lex-string-control.tsv

# A `not-shared:` line declares a filename that exists on BOTH sides and
# names two DIFFERENT fixtures. Give the PARSER-side name (unlike a plain
# line above, which may be spelled either side's way). The content comparison is then skipped —
# and only then. A plain line above cannot do this, deliberately: nothing
# here may be read as "this shared fixture is allowed to drift".
#
# Both repos keep an ADR-14 divergence register at this name, and they
# are the same IDEA rather than the same file: jsonic's rows are
# `input -> parse result` against its grammar, while this engine ships no
# grammar and its rows carry a `probe` column naming which observation
# they make. Neither runner could consume the other's file. The shared
# name is the point — a reader who knows one repo's register should find
# the other's without looking it up.
not-shared: divergent.tsv
